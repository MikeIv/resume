## 4. Реальность hh.ru (проверено в фазе 2)

- Публичное API вакансий закрыто: `GET /vacancies` отдаёт `403 forbidden` даже с
  корректными заголовками. Методы для соискателей из документации `hhru/api`
  удалены.
- Автоматизированный сбор данных нарушает п. 6.1.38 пользовательского соглашения
  hh. Поэтому всё, что касается откликов, — **только браузер с участием человека**,
  без парсинга и без скрытых запросов. Полноценный автопилот — фаза 4, и в нём
  обязательны режим ревью, лимиты и остановка по капче.
- Лимит обращений к API — 200 запросов в сутки на приложение; для чтения профиля
  это не нужно (профиль читается глазами в браузере).
- В резюме hh есть лимиты полей (заголовок ≈ 100 символов, навыки ≈ 30 тегов) —
  проверять по счётчику в интерфейсе, а не по памяти.
- Бесплатный подъём резюме — каждые 4 часа; «Портрет кандидата» AI-ассистента
  строится из 6 обязательных и 4 желаемых критериев.

## 5. План фазы 3 (по шагам)

### Шаг 1. Логин в hh (человек)

Агент создаёт `scripts/hh-login.ts`: Playwright с `headless: false` и
`launchPersistentContext` в `.dsh/hh-profile` (каталог в `.gitignore`), открывает
`https://hh.ru/account/login`. **Логин, пароль и код из SMS вводит человек** —
агент не спрашивает и не хранит их. После успешного входа сохраняется
`storageState` в `.dsh/hh-profile/state.json` и делается скриншот профиля.

Проверить: в `.gitignore` есть `.dsh/`, `*.env`; секреты в репозиторий не попадают.

### Шаг 2. Снять текущее состояние профиля

Прочитать в браузере (глазами, скриншотами в `docs/hh/`):

1. Заголовок резюме, желаемая должность, специализации, зарплата.
2. Видимость резюме, дата обновления, статус поиска.
3. «О себе» — текущий текст.
4. Ключевые навыки — список тегов.
5. **Образование** (учебное заведение, факультет, специальность, год окончания).
6. **Языки** (язык, уровень).
7. Опыт работы — сверить с `data/resume.yaml`: нет ли пропущенных мест и
   расхождений в датах.

### Шаг 3. Заполнить данные сайта

Перенести образование и языки в `data/resume.yaml` (схема уже поддерживает
`education[]` и `languages[]`), прогнать `pnpm build:all`, убедиться, что PDF
остался на 2 страницах и `check:pdf` зелёный. Если образование добавляет строки —
проверить, что раздел «Образование и языки» появился в PDF и на странице `/ats`.

### Шаг 4. Собрать hh-пакет и сверить лимиты

`pnpm hh:pack` → `docs/hh-profile-pack.md`. Проверить, что каждый блок влезает в
поле hh: заголовок ≤ 100 символов, «О себе» ≤ 5000, навыки ≤ 30 тегов. Если
блок длиннее — сокращать с конца, сохраняя технологии и цифры.

Дописать в пакет:

- «Портрет кандидата» для AI-ассистента: 6 обязательных и 4 желаемых критериев
  (роль, стек, опыт, формат, город, зарплата; плюс желаемые: домен, продукт,
  команда, процесс).
- Чек-лист видимости: открыть резюме для всех, поднять бесплатно, проверить
  поиск по `POSITION:` и `KEYWORDS:`.

### Шаг 5. Человек обновляет профиль, агент проверяет

Порядок: заголовок → специализации и зарплата → «О себе» → навыки → образование
и языки. После каждого блока — скриншот в `docs/hh/` (до/после). Агент сверяет
внесённое с `docs/hh-profile-pack.md` и фиксирует расхождения.

### Шаг 6. Закрыть фазу

`pnpm verify` + `pnpm build:all`, обновить отчёт: что изменено на hh, какие
данные добавлены в YAML, где скриншоты. Коммит — **только по слову «коммить»**,
сообщение на английском (Conventional Commits). В отчёте указать хеш и заголовок.

## 6. Технические ограничения песочницы

- PowerShell под DSH: запуск `pnpm`, `nuxt`, `vitest`, `playwright`, `eslint`
  падает с EPERM на пайпах. Такие команды запускать с
  `sandbox_permissions: danger-full-access` и коротким обоснованием на русском.
- Обычные чтения/правки файлов — в обычном режиме, повышение прав не нужно.
- Playwright-браузеры уже установлены (chromium). Для hh нужен `headless: false`.
- Локальное превью сайта: `pnpm preview` (порт 3000) в фоновом задании.
- Скриншоты для проверки: `pnpm screenshot` → `.preview/` (в `.gitignore`).

## 7. Запреты

- **Не публиковать** СНИЛС, паспортные данные, полную дату рождения; в текстах
  резюме не должно быть телефона и почты внутри абзацев о себе и достижениях
  (это проверяет тест).
- Не выдумывать цифры и проекты: только измеримые факты (коммиты, файлы, тесты,
  Lighthouse) и то, что подтверждается репозиториями. Клиенты под NDA — без имён
  и цифр, только стек и характер работы.
- Не автоматизировать отклики и не парсить hh вне рамок фазы 4 и без режима
  ревью; не обходить капчу.
- Не коммитить без команды «коммить», не пушить без «пушь», не менять
  `data/resume.yaml` под чужие ожидания без согласования.
- Не редактировать `AGENTS.md` руками — он генерируется (`pnpm rules:sync`).
